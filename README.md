# Agentic Orchestration Framework & Multi-Agent SDLC

An enterprise-grade, stateful multi-agent orchestration framework built with **LangGraph** and **Groq (LLaMA 3)**. This system automates the Software Development Life Cycle (SDLC)—from natural language architectural planning to code generation, automated review loops, file writing, and human-in-the-loop (HITL) governance.

---

## Architecture & Multi-Agent Graph

The framework operates as a stateful graph managed by LangGraph, enforcing governance checkpoints and self-correction cycles:

```text
[User Requirement]
       │
       ▼
┌───────────────┐
│  Planner Node │ ──► Generates architectural plan & tech stack breakdown
└───────────────┘
       │
       ▼ (HITL Checkpoint: interrupt())
┌───────────────┐
│ Approval Node │ ──► Pauses for Human-in-the-Loop review (Approve / Reject + Feedback)
└───────────────┘
       │
       ├─────────────────────────┐ (If Rejected)
       │ (If Approved)           ▼
       │                  ┌───────────────┐
       │                  │ Planner Loop  │ (Re-architects based on feedback)
       │                  └───────────────┘
       ▼
┌───────────────┐
│  Coder Node   │ ──► Generates multi-file Java 17 / Spring Boot 3 code
└───────────────┘
       │
       ▼
┌───────────────┐
│ Reviewer Node │ ──► Audits code for syntax errors, missing dependencies, & edge cases
└───────────────┘
       │
       ▼
┌───────────────┐
│  Writer Node  │ ──► Persists validated code to the generated_project/ directory
└───────────────┘
```

Failed reviews route back to the **Coder Node** (bounded retry loop via `increment_retry`) before the **Writer Node** persists output.

## Project Directory Structure

```text
Agent-Orchestration-Assesment/
├── orchestrator/
│   ├── graph.py         # LangGraph state machine definition & checkpointing
│   ├── nodes.py         # Planner, Coder, Reviewer, and File Writer agent nodes
│   ├── state.py         # Shared state graph definitions
│   ├── llm.py           # Groq client factory & connectivity check
│   └── file_writer.py   # Parses ### File: blocks and writes to disk
├── scripts/
│   ├── run_scenarios.py # Interactive greenfield scenario runner
│   └── run_hitl_demo.py # Automated HITL governance regression tests (Approved/Rejected)
├── generated_project/   # Output Spring Boot 3 microservice generated by the agents
├── .env                 # Environment variables (Groq API key and model config)
└── README.md
```

## Prerequisites

- Python 3.10+ with pip and virtual environment support
- Java 17 Development Kit (JDK 17) for compiling and testing the generated code
- Apache Maven for dependency management and build verification
- A Groq API Key (configured for LLaMA 3 models)

---

## Setup

1. Create a virtual environment and install Python dependencies:

   ```bash
   python -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. Configure environment variables — create a `.env` file in the root directory:

   ```bash
   cp .env.example .env
   ```

   ```env
   GROQ_API_KEY=your_groq_api_key_here
   GROQ_MODEL=llama-3.1-8b-instant
   ```

   Get a free key at [Groq Console](https://console.groq.com/keys).

## Running the Framework

### 1. Interactive Greenfield Scenario

Run the end-to-end interactive CLI runner to trigger the multi-agent workflow with a URL shortener requirement profile:

```bash
python scripts/run_scenarios.py --scenario greenfield
python scripts/run_scenarios.py --scenario brownfield
python scripts/run_scenarios.py --scenario ambiguous
```

### 2. Human-in-the-Loop (HITL) Approved Flow Demo

Test the governance checkpoint where an automated script simulates human plan approval:

```bash
python scripts/run_hitl_demo.py --scenario approved
```

### 3. Human-in-the-Loop (HITL) Rejection & Feedback Loop Demo

Test the feedback loop where a human rejects the initial plan and forces the Planner to re-architect:

```bash
python scripts/run_hitl_demo.py --scenario rejected
```

## Verifying the Generated Codebase

The framework automatically writes generated microservices into the `generated_project/` directory. To compile and execute the test suite (JUnit 5 + Mockito via Maven) for the generated service:

```bash
cd generated_project
mvn clean test
```

To run the microservice locally:

```bash
mvn spring-boot:run
```
